# 한 방보다 빠른 반복

> VIBE CODING · 07 · 프롬프트 & 개선 루프

바이브코딩의 진짜 실력 — 완벽한 프롬프트가 아니라, 빠른 반복으로 원하는 결과에 수렴시키는 실행-피드백-개선 루프.

---

## 01. 3단계 루프

```
  ① 실행
        │
        ▼
  ② 피드백(확인)      반복
        │              ▲
        ▼              │
  ③ 개선(재지시) ──────┘
```

대충 시키고 → 결과를 눈으로 보고 → 콕 집어 고친다. 이 순환이 바이브코딩의 리듬.

초보자는 ①에서 완벽하려 지칩니다. 고수는 **대충 시키고 빠르게 ②③을 돕니다.**

---

## 02. 좋은 프롬프트 4요소

| 요소 | 설명 | 예 |
|------|------|-----|
| 목표(What) | 무엇을 원하나 | "로그인 폼을 만들어줘" |
| 맥락(Context) | 어떤 상황·파일 | "`@LoginForm.tsx` 기준으로" |
| 제약(Constraints) | 지켜야 할 규칙 | "외부 라이브러리 없이, Tailwind로" |
| 형식(Format) | 결과 모양 | "검증 포함, 에러 메시지 한국어" |

> **"회원가입 만들어줘"** →
> "`@SignupForm.tsx`에 회원가입 폼을 만들어줘. 이메일 형식·비밀번호 8자 이상 검증, 실패 시 한국어 에러 문구, 제출 중엔 버튼 비활성화. Tailwind만 사용."

---

## 03. 개선 프롬프트 패턴

- **구체적 수정**: "3번째 버튼만 빨간색으로, 나머지는 그대로."
- **부분 되돌리기**: "방금 바꾼 정렬은 원래대로, 색만 유지."
- **원인 질문**: "왜 이렇게 구현했어? 더 간단한 방법 없어?"
- **제약 추가**: "좋아. 이제 모바일에서도 안 깨지게."
- **예시 제시**: "이런 느낌이야: [스크린샷]. 참고해."

---

## 04. 막힐 때 & 흔한 실수

| 실수 | 교정 |
|------|------|
| 한 번에 너무 많이 시킴 | 기능 단위로 쪼개기 |
| 결과 실행 안 하고 다음 지시 | 항상 눈으로 확인 후 진행 |
| 엉킨 대화를 계속 붙잡음 | 새 대화 또는 체크포인트 복귀 |
| 컨텍스트 없이 요청 | `@`로 관련 파일 첨부(05강) |
| 같은 지시 매번 반복 | Rules로 승격(06강) |

> **정리** — 프롬프트 4요소로 시작하고, 결과를 보고, 개선 패턴으로 좁혀간다. **완벽한 지시가 아니라 빠른 루프**가 목적지에 데려다준다.

## 직접 따라하기 — 룰북 실습

나쁜 vs 좋은 프롬프트를 각각 요청해 결과 차이를 직접 느껴보세요. (Agent 모드)

**1) 나쁜 프롬프트 (두루뭉술)**

```
버튼 하나 만들어줘.
```

**2) 좋은 프롬프트 (목표·맥락·제약·형식)**

```
이 폴더에 button.html 파일을 만들어줘.
- 목표: "구독하기" 버튼 하나
- 제약: 외부 라이브러리 없이 순수 HTML/CSS
- 형식: 가운데 정렬, 둥근 모서리, 마우스 올리면 색이 진해짐,
        클릭하면 "구독 완료!" alert
```

**3) 개선 3연타 (하나씩)**

```
버튼 색을 파란색으로 바꿔줘.
```

```
좋아. 이제 버튼에 마우스를 올리면 살짝 어두워지게.
```

```
방금 넣은 그림자는 빼줘. 나머지는 그대로.
```
