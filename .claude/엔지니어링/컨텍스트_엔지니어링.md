# 무엇을 담을까의 기술

> VIBE CODING · 13 · 컨텍스트 엔지니어링 · 필수

"어떤 단어를 쓸까"(프롬프트)를 넘어 "어떤 정보를 어떻게 배치할까"(컨텍스트)로. 2025~2026년, AI 에이전트 성패를 가르는 가장 큰 변수로 꼽히는 개념입니다.

---

## 01. 프롬프트 vs 컨텍스트 엔지니어링

프롬프트 엔지니어링이 "어떤 단어로 물을까"에 집중한다면, 컨텍스트 엔지니어링은 한 단계 위 — "AI가 답하기 전에 어떤 정보 묶음을 보게 할까"를 설계하는 일입니다.

| 구분 | 프롬프트 엔지니어링 | 컨텍스트 엔지니어링 |
|------|-------------------|---------------------|
| 질문 | "무슨 말을 쓸까" | "무슨 정보를 담을까" |
| 범위 | 한 번의 요청 | 대화·도구·시간 전체 |
| 적합 | 일회성 작업 | 복잡한 에이전트 작업 |

**정리** — 프롬프트가 "질문을 잘 던지기"라면, 컨텍스트 엔지니어링은 회의 전에 참고자료·이전 회의록·역할을 책상에 미리 깔아두는 것입니다. 자료가 잘 갖춰지면 어떤 질문에도 좋은 답이 나옵니다.

---

## 02. 왜 지금 중요한가

업계에서는 "2025년 AI 에이전트 성공의 가장 큰 예측 변수는 모델 선택이 아니라 컨텍스트 엔지니어링"이라고 말합니다. 이유는 간단합니다 — 아무리 똑똑한 모델도 맥락이 부실하면 엉뚱한 답을 냅니다.

- 같은 모델도 **무엇을 보여주느냐**에 따라 결과가 천차만별
- 에이전트는 여러 턴·도구·기억을 오가므로 **맥락 관리**가 핵심
- 5강이 신뢰를 다뤘다면, 13강은 그 맥락을 채우는 법으로 좁혀옵니다

---

## 03. 4가지 전략 — 쓰기·고르기·줄이기·나누기

LangChain은 컨텍스트를 다루는 방법을 네 가지로 정리했습니다.

| 전략 | 뜻 | Cursor에서 |
|------|-----|-----------|
| **Write** (쓰기) | 지침·계획을 명시적으로 적어둠 | Rules(06), 계획을 문서로 작성 |
| **Select** (고르기) | 지금 작업에 필요한 것만 정부 | `@파일` · `@Codebase`(05) |
| **Compress** (줄이기) | 긴 내용을 요약해 토큰 절약 | "핵심만 3줄로", 대화 압축 |
| **Isolate** (나누기) | 관련 없는 맥락은 분리 | 주제별 새 대화(03) |

---

## 04. 초보도 지키는 3원칙

1. **필요한 것만, 정확히.** 많이 담을수록 좋은 게 아닙니다 (노이즈↑).
2. **중요한 건 앞이나 끝에.** AI는 긴 입력의 중간을 잘 놓칩니다.
3. **주제가 바뀌면 새 대화.** 낡은 맥락이 답을 흐립니다.

**정리** — 컨텍스트 엔지니어링은 모델의 "작업 책상"에 무엇을·어떻게 올릴지 설계하는 일. 4전략(쓰기·고르기·줄이기·나누기)으로 관리한다.

---

## 직접 따라하기 — 룰북 실습

컨텍스트를 "설계"하는 감각을 채팅에서 연습해보세요.

**1) 계획을 먼저 쓰게 하기 (Write)**

```
코드를 짜기 전에, 이 기능을 만들기 위해 필요한 파일·단계·전략을
먼저 번호로 매겨 정리해줘. 내가 확인 후 진행할게.
```

**2) 컨텍스트 줄이기 (Compress)**

```
지금까지 대화가 길었으니 현재 상황만 5문장으로 요약해줘.
이걸 앞으로의 기준으로 삼자.
```

**3) 관련 자료만 고르기 (Select)**

```
@Codebase 이 작업과 직접 관련된 파일만 3개 이내로 골라주고,
왜 그 파일이 필요한지 말해줘.
```

> "많이가 아니라 정확히" — 무관한 맥락을 넣지 않는 것도 실력입니다.
