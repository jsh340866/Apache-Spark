# AI를 감싸는 시스템 (심화)

> VIBE CODING · 14 · 프로 심화 · 필수

모델은 "두뇌" 하나일 뿐. 그 두뇌에 도구를 쥐어주고, 결과를 확인하고, 상태를 기억하고, 위험을 막는 "몸통"이 하네스입니다. Cursor·Claude Code가 잘 되는 진짜 이유.

---

## 01. 하네스의 해부학

하네스는 대략 이런 계층으로 구성됩니다.

```
의도 포착(사용자 요청) → 사양화(무엇을 만들지 명세) → 컴파일(컨텍스트 조립)
→ 실행(도구 호출 루프) → 검증(테스트·리뷰) → 지속(상태 저장)
```

Anthropic은 자사 **Claude Agent SDK**를 "코딩을 비롯한 도구 사용 작업에 능한 범용 에이전트 하네스"로 설명하며, **컨텍스트 컴팩션·도구 디스패치·세션 관리·진행 추적**을 처리한다고 밝힙니다.

---

## 02. 컨텍스트 컴팩션과 상태

루프가 길어지면 컨텍스트 창이 가득 찹니다. 하네스는 **컴팩션**으로 오래된 대화를 요약해 자리를 비웁니다(13강과 직결). 또한:

- **체크포인트**: 단계별 스냅샷으로 되돌리기(04)
- **메모리 파일**: 세션이 끝나도 결정을 파일로 남겨 다음에 다시 로드
- **진행 추적**: 할 일 목록(todo)을 유지하며 장기 작업 수행

---

## 03. 도구 설계와 권한 경계

하네스 품질의 상당 부분은 **"어떤 도구를, 어떤 설명으로, 어떤 권한으로"** 노출하느냐에 달려 있습니다.

| 요소 | 왜 중요 |
|------|---------|
| 도구 설명 | 모델이 언제 쓸지 판단하는 근거 — 명확할수록 정확 |
| 권한 게이트 | 쓰기·삭제·외부 전송은 승인 필요(18) |
| 실패 피드백 | 에러를 구조적으로 되돌려줘야 자가 수정 가능 |

> **주의** — 자율성이 클수록 잘못된 방향으로 멀리 갈 수 있습니다. 그래서 검증 게이트와 권한 경계가 하네스의 필수 요소입니다.

---

## 04. 모델 vs 하네스 — 어디까지가 누구 몫?

연구들은 하네스가 좋으면 상대적으로 **약한 모델로도** 좋은 성능을 내고, 반대로 하네스가 부실하면 **강한 모델도** 헤맨다고 봅니다. 즉 실무 성능은 **모델 × 하네스**의 곱입니다.

> **연결** — 좋은 하네스의 3요소가 이 커리큘럼의 다음 강들입니다 — 규칙(15)·검증(17)·안전(18). 그리고 하네스를 여러 개로 확장하면 오케스트레이션(19)이 됩니다.

## 직접 따라하기 — 룰북 실습

하네스가 잘 돌게 "재료"를 주는 프롬프트를 연습해보세요. (Agent 모드)

**1) 검증 통로 주기 (자가 수정 유도)**

```
이 기능을 구현하고, 테스트를 작성해 실행해줘. 테스트가 통과할 때까지
스스로 고쳐줘. 각 시도마다 무엇을 바꿨는지 한 줄로 알려줘.
```

**2) 진행 상태를 남기게 하기 (상태 유지)**

```
지금까지 진행 상황과 다음 할 일을 progress.md 파일에 체크리스트로
정리해줘. 작업하면서 계속 업데이트해줘.
```

**3) 권한 경계 확인 (안전)**

```
파일을 삭제하거나 외부로 데이터를 보내는 명령은 실행하기 전에
반드시 먼저 나에게 무엇을 왜 하는지 물어봐.
```

> 이 세 가지(검증·상태·권한)가 하네스가 잘 돌게 하는 핵심 재료입니다.
