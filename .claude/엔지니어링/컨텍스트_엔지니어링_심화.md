# 무엇을 담을까의 기술 (심화)

> VIBE CODING · 13 · 프로 심화 · 필수

"어떤 단어를 쓸까"(프롬프트)를 넘어 "어떤 정보를 어떻게 배치할까"(컨텍스트). 2025~2026년, AI 에이전트 성패를 가르는 가장 큰 변수로 꼽히는 개념입니다.

---

## 01. 컨텍스트 윈도우와 그 안의 구성

LLM은 **컨텍스트 윈도우**(한 번에 볼 수 있는 토큰 한계) 안에서만 사고합니다. 이 창에 들어가는 것들:

| 구성 요소 | 예 |
|-----------|-----|
| 시스템 지침 | Rules · AGENTS.md · 역할 |
| 검색된 지식 | `@Codebase` · `@Docs` · RAG |
| 기억(memory) | 이전 결정·요약 |
| 도구 설명·결과 | MCP 툴·실행 출력 |
| 대화 이력 | 직전 메시지들 |

컨텍스트 엔지니어링은 이 창을 **"올바른 정보로, 구조적으로"** 채우는 규율입니다.

---

## 02. 컨텍스트 로트(rot) — 길수록 나빠진다

모델은 컨텍스트를 **균일하게 쓰지 않습니다.** 입력이 길어질수록 성능이 불안정해지고(=컨텍스트 로트/성능 저하), 특히 **중간에 있는 정보를 놓치는** 경향(lost-in-the-middle)이 보고됩니다.

> **함의** — "일단 다 넣으면 되겠지"는 틀렸습니다. **무관한 토큰이 중요한 신호를 밀어내고 희석**합니다. 그래서 Compress·Isolate가 중요합니다.

**배치 원칙**

```
[핵심 지침] → [필요 자료] → … → [질문/현재 작업]
```

중요한 지침은 맨 앞, 지금 할 일은 맨 끝에 두는 걸 뜻한다.

---

## 03. 에이전트에서의 컨텍스트 생애주기

에이전트는 여러 턴을 돌며 컨텍스트가 계속 쌓입니다. 이를 관리하는 기법:

- **컴팩션(compaction)**: 오래된 대화를 요약으로 압축해 창을 비운다 (하네스가 자동 처리 — 14강).
- **검색 기반 주입(RAG)**: 전부 넣지 않고 질문에 맞는 조각만 검색해 넣는다 (`@Codebase`의 원리).
- **메모리 파일**: 중요한 결정을 파일에 적어 다음 세션에 다시 로드한다.
- **서브에이전트 격리**: 하위 작업은 별도 컨텍스트에서 처리해 본류를 깨끗이 유지 (19강).

| 전략 | Cursor 기능 |
|------|-------------|
| **Write** | `.cursor/rules`, 계획을 md로 먼저 작성 |
