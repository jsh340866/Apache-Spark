## 이슈 만들기전 참고사항

| 타입         | 의미             | 예시                |
| ---------- | -------------- | ----------------- |
| `feat`     | 새로운 기능 추가      | 회원가입 기능 추가        |
| `fix`      | 버그 수정          | 로그인 오류 수정         |
| `refactor` | 기능 변화 없이 코드 개선 | 생성자 주입으로 변경       |
| `docs`     | 문서 수정          | README 수정         |
| `style`    | 코드 스타일 변경      | 들여쓰기, 세미콜론 정리     |
| `test`     | 테스트 코드 추가/수정   | JUnit 테스트 작성      |
| `chore`    | 기타 작업          | Gradle 버전 변경      |
| `perf`     | 성능 개선          | 쿼리 최적화            |
| `build`    | 빌드 관련          | Gradle/Maven 수정   |
| `ci`       | CI/CD 설정       | GitHub Actions 수정 |

- 이슈 체크리스트 생성시 해당 타입을 앞에 붙여 가독성 올리기( 예시 -> feat: 회원가입 API 추가 )
- 이슈 만들라고 명령하면 md파일로 저장하기 
- 이슈는 만들기만 하고 따로 Github에 올리지 않는다.
- 이슈 문서의 "작업 범위" 항목은 `-` 대신 `1. 2. 3.` 번호 목록으로 작성한다.
