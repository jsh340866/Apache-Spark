### 1단계 — Company 업종코드·업종명·대표자명 수집 (⚠️ 아직 커밋 안 됨)

**변경 파일 (미커밋 상태):**
- `Company.java` — `induty_code`, `induty_nm`, `ceo_nm` 컬럼 추가 + `setIndustryInfo(indutyCode, indutyNm, ceoNm)` setter 메서드 추가
- `DartCompanyCollector.java` — 4단계(KRX+corpCode 저장) 뒤에 5단계 `collectIndustryInfo()` 추가
  - DB에 저장된 Company 페이징 조회 → corpCode로 DART `company.json` 호출 → `induty_code`, `ceo_nm` 받아옴
  - `induty_code` 앞 2자리(중분류)로 `INDUTY_NAME_MAP`(KSIC 10차 개정 74개 코드 전체) 조회해서 `induty_nm` 계산
  - setter로 managed 엔티티 직접 수정 후 save (dirty checking, merge 불필요)
  - 호출 간격 100ms sleep (DartFinancialCollector와 동일 패턴)
- `CollectorTest.java` — 테스트 날짜 조정 (t4, t5, t6)

**중요 발견 사항 (외부 API 검증 결과):**
- DART `company.json` 실제 호출 결과: `induty_code`만 제공, `induty_nm`(업종명)은 API에 없음 (공식 개발가이드도 항목명·설명 둘 다 "업종코드"로만 표기)
- `induty_code`는 KSIC(한국표준산업분류) 코드지만, 회사마다 등록 깊이가 다름 (3자리 소분류/4자리 세분류/5자리 세세분류 혼재) → 항상 동일 레벨인 앞 2자리(중분류)만 잘라 써야 함
- KSIC 코드표 조사 중 **9차 개정(2007~2017, 폐지됨) 파일을 잘못 받았던 해프닝 있음** → 통계청 공식 가이드북 PDF로 10차 코드 재검증 완료. 자세한 과정과 전체 코드-이름표는 [업종코드_KSIC_중분류_매핑_20260702.md](../docs/업종코드_KSIC_중분류_매핑_20260702.md) 참고
- `ceo_nm`은 "각자대표"/"공동대표" 표기가 있는 회사도 있고 없는 회사도 있음 (DART 공시 등록 방식 차이, 필드 자체 한계)

**테스트 결과:** 사용자가 `t1_기업정보수집()` 직접 실행해서 확인 완료. 초기엔 induty_code/ceo_nm 없는 값 있는지 우려했으나 확인해보니 전부 정상 저장됨.

**다음 세션에서 먼저 할 일**: 위 미커밋 변경사항 커밋할지 확인 필요.
