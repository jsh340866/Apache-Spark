# 작업요약 — 배포 준비 및 스케줄러/데이터 버그 정비 (2026-07-27)

> 외부 API 키 하드코딩 제거, Docker/Nginx/Jenkins 배포 환경 구성, 스케줄러 타임존 명시, `@EnableScheduling`/`@EnableAsync` 활성화를 진행하고, 그 과정에서 발견된 Top100/네이버 시세 버그를 같이 수정함. (커밋 미완료 — 작업 트리 기준)
>
> JWT 서명키·계정(로그인/회원) 관리 로직은 참여하지 않아 이 문서에서 제외함.

## 변경 내용

### 1. 외부 API 키 하드코딩 제거
- `application.properties`의 DART/공공데이터/한국수출입은행/KRX API 키를 전부 `${ENV_VAR}` 참조로 교체.
- `.gitignore`에 `application-local.properties`, `application-prod.properties`, `.env` 추가 — 실제 값은 커밋 대상에서 제외.

### 2. Docker Compose / Dockerfile 구성
- 운영용 `docker-compose.yml`과 로컬 개발용 `docker-compose-local.yml`을 분리 작성. 서비스는 `db`(MySQL 8.0) / `fn`(Nginx, 프론트) / `bn`(Spring Boot 백엔드) 3개.
- custom bridge network(`172.30.0.0/24`)에 컨테이너별 고정 IP 할당(db `.10`, fn `.30`, bn `.40`).
- `depends_on: condition: service_healthy`로 기동 순서를 강제: db 헬스체크 통과 → bn 기동 → bn 헬스체크(`/actuator/health`) 통과 → fn 기동. DB가 완전히 뜨기 전에 백엔드가 붙거나, 백엔드가 준비되기 전에 프론트(nginx)가 트래픽을 받는 상황을 방지.
- 위 헬스체크가 호출하는 `/actuator/health`를 제공하기 위해 `build.gradle`에 `spring-boot-starter-actuator` 의존성 추가.
- `valuepick/Dockerfile`: `gradle:8.14.1-jdk21`로 빌드하고 `eclipse-temurin:21-jdk-alpine`으로 실행하는 멀티스테이지 구성. 타임존은 `TZ=Asia/Seoul` 환경변수와 `-Duser.timezone=Asia/Seoul` JVM 옵션으로 고정.
- `front/Dockerfile`(운영 — Let's Encrypt 인증서 볼륨 마운트 전제) / `front/Dockerfile.local`(로컬 — SSL 없이 HTTP만)을 분리. 현재는 정적 HTML/CSS/JS를 `nginx:alpine` 이미지에 그대로 복사하는 방식이고, React 빌드 스테이지는 전환 대비용으로 주석 처리해둠.
- `db/Dockerfile`: MySQL 8.0 공식 이미지 기반, 계정 정보는 이미지에 굽지 않고 compose의 `env_file`로 런타임 주입.

### 3. Nginx 설정
- `front/nginx.conf`(운영): 80 → 443 HTTPS 리다이렉트, Let's Encrypt 인증서로 TLS 종료(`ssl_certificate`/`ssl_certificate_key`), `/`는 React SPA 정적 파일 서빙(`try_files $uri /index.html`), `/bn/`은 `proxy_pass`로 `bn-container:8080`에 리버스 프록시.
- `front/nginx-local.conf`(로컬): SSL 없이 HTTP(80)만 서빙, 정적 파일 서빙과 `/bn/` 프록시 구조는 동일.
- 인증서 갱신용 `/.well-known/acme-challenge/` 경로는 HTTPS 리다이렉트 예외 처리.

### 4. Jenkins CI/CD
- GitHub Webhook 수신 → `main` 브랜치 변경 감지 시 EC2 내부 Jenkins 파이프라인 자동 실행.
- 파이프라인 단계: Checkout(`git pull main`) → Build(`gradle build -x test`) → Docker Build(`docker-compose build`) → Deploy(`docker-compose up -d`).
- 참고: 실제 Jenkinsfile/파이프라인 스크립트는 이 저장소에 커밋되어 있지 않아(Jenkins 잡 설정으로 별도 관리) 위 단계는 `docs/배포 파이프라인.html` 문서 기준으로 확인한 내용임.

### 5. 스케줄러 타임존 명시
- 전체 스케줄러(Company/Dividend/Exchange/Financial/Indicator/MarketIndex/StockPrice/Top100/UserCleanup)의 `@Scheduled(cron = ...)`에 `zone = "Asia/Seoul"` 추가.
- 서버 인스턴스의 OS 타임존이 KST가 아닐 경우(예: EC2 기본 UTC) 크론 표현식이 의도한 시각과 다르게 실행되는 문제를 원천 차단.

### 6. `@EnableScheduling` / `@EnableAsync` 활성화
- `DemoApplication`, `AsyncConfig`에서 주석 처리되어 있던 두 애노테이션을 다시 켬 — 이게 꺼져 있으면 스케줄러/비동기가 전부 동작하지 않는 전제 조건.

### 7. 데이터 버그 수정
- **Top100Repository**: TOP10/전체 랭킹 조회 쿼리에 `WHERE t.base_dt >= (SELECT MAX(base_dt) FROM TOP100)` 조건 추가 — 기존엔 여러 배치 날짜의 데이터가 섞여 조회될 수 있었는데, 최신 배치 날짜만 보도록 수정.
- **Top100Service**: 랭킹 후보 필터에 `corp_cls == "Y"`(코스피/유가증권시장) 조건 추가 — 코스닥 등 다른 시장 종목이 랭킹에 섞이는 걸 제외.
- **SimpleInfoServiceImpl**: 네이버 실시간 시세 등락률 부호 로직 수정. 기존엔 `rf` 코드 `2`/`5`만 처리했는데, `1`(상승)/`4`(하락) 코드가 빠져 있어서 잘못된 부호가 나올 수 있었음 — `1,2`는 양수, `4,5`는 음수로 매핑하도록 수정.
- **DartFinancialCollector**: DART API 재시도 횟수 `1` → `3`.

### 8. 기타
- `valuepick/valuepick/` 하위에 중복으로 남아있던 gradle wrapper(`gradlew`, `gradlew.bat`, `gradle-wrapper.properties`) 삭제.

## 기술적 의사결정 사항

### (1) 스케줄러 타임존: 서버 로케일 의존 → 명시적 `Asia/Seoul` 고정
- **문제**: 지금까지 크론식은 서버 JVM/OS의 기본 타임존에 의존했음. 로컬 개발 PC는 KST라 문제가 안 드러났지만, 배포 대상 서버(EC2 등)가 UTC로 뜨면 예를 들어 "새벽 1시 20분 주가 수집"이 실제로는 낮 10시 20분에 실행되는 등 스케줄 전체가 어긋남.
- **결정**: 모든 `@Scheduled`에 `zone = "Asia/Seoul"`을 명시해 서버 환경에 무관하게 동일한 시각에 실행되도록 고정.

### (2) Top100 랭킹 쿼리: `MAX(base_dt)` 필터를 뒤늦게 추가한 이유
- **배경**: 원래 쿼리는 `ORDER BY score DESC`만 있어서, 배치가 여러 날짜에 걸쳐 쌓인 TOP100 데이터 중 어떤 날짜의 것이든 점수만 높으면 랭킹에 노출될 수 있는 구조였음 (예: 오늘자 데이터가 비거나 늦게 들어오면 며칠 전 데이터가 섞여 보임).
- **결정**: `base_dt >= (SELECT MAX(base_dt) FROM TOP100)` 조건을 추가해 "가장 최근 배치 날짜"만 랭킹 대상이 되도록 강제. 별도 컬럼 캐싱이나 애플리케이션 레벨 필터링 대신 서브쿼리로 처리해 스키마 변경 없이 해결.

## 참고
- 위 변경은 전부 작업 트리(unstaged) 상태 — 아직 커밋되지 않음.
- 컴파일/배치 실행 테스트는 이번 세션에서 별도로 수행하지 않음. 배포 전 `./gradlew build` 및 스케줄러 동작 확인 필요.
- 환경변수(`DART_API_KEY`, `STOCK_API_KEY`, `KOREAEXIM_API_KEY`, `KRX_API_KEY`)는 실제 배포 서버(EC2 등)에 별도로 주입되어 있어야 함 — 이 세션에서는 값 자체를 확인하지 않았음.
