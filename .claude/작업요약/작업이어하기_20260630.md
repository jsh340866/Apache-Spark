## 0단계 — StockPriceCollector 벌크 전환 (최우선)

**확인 완료:**
- 공식 API 파라미터 문서 확인 → `likeSrtnCd`는 선택 필터, 필수값 아님
- `basDt` + `numOfRows=4000`만으로 해당일 전 종목 한 번에 수신 가능
- 오늘 `"API token quota exceeded"` 응답은 방식이 틀린 게 아니라 일일 한도 초과였음

**작업 내용:**

`StockPriceCollector` ([StockPriceCollector.java](../src/main/java/com/example/demo/domain/service/StockPriceCollector.java)) 리팩토링:

```java
// 현재: 전 종목 루프 × 종목당 API 1번 = 2,700번/일
for (Company company : companies) {
    requestApi(company.getStockCode(), date);
}

// 개선: 날짜 1번 호출 → 전 종목 응답 파싱
// numOfRows=4000, basDt=date, likeSrtnCd 제거
```

- XML 방식 → **JSON 방식으로 전면 교체** (`resultType=json`)
- `StockPriceXmlParser` 클래스 **삭제** (XML 파서 불필요)
- `buildUrl()`에서 `likeSrtnCd` 제거, `numOfRows=4000`, `resultType=json` 추가
- 응답을 `Map<String, Object>`로 받아 items 리스트 파싱 (DartCompanyCollector의 KRX 수집 방식과 동일 패턴)
- Company 테이블의 stock_code와 매칭해서 저장 (스팩·리츠 자동 제외)
- 전 종목 루프 제거 → 날짜당 1회 호출
- 모멘텀 팩터 구현 시 1개월 전·12개월 전 날짜도 각 1번 호출로 해결

### 1단계 — Company 업종코드 추가

**배경:**
- 현재 TOP100 스코어링이 전 업종을 섞어서 백분위 계산 → 금융주·성장주 구조적 불리
- DART `/api/company.json` 에서 `induty_code` 필드 확인 완료 (삼성전자 = `"264"`)
- KRX API에는 업종코드 없음 (확인 완료)

**작업 내용:**

`Company` 엔티티 ([Company.java](../src/main/java/com/example/demo/domain/entity/Company.java)):
```java
// 추가할 컬럼
@Column(name = "induty_code", length = 10)
private String indutyCode;
```

`DartCompanyCollector` ([DartCompanyCollector.java](../src/main/java/com/example/demo/domain/service/DartCompanyCollector.java)):
- 현재 `collectCompanies()` 4단계(KRX + DART corpCode.xml → DB 저장) 구조
- **추가할 5단계**: 저장된 Company의 `corpCode`로 DART `/api/company.json` 호출 → `induty_code` 저장
- API: `https://opendart.fss.or.kr/api/company.json?crtfc_key={dartApiKey}&corp_code={corpCode}`
- 응답 필드: `induty_code` (숫자 문자열, 예: `"264"`)
- `dart.api.key` 이미 있음

**주의:**
- `ddl-auto=update` 환경이므로 컬럼 추가는 안전 (기존 데이터 null로 유지)
- 전 종목 API 호출이라 DART 호출 간격(sleep) 필요
- 수집 후 `t1_기업정보수집()` 테스트로 재수집 실행

### 3단계 — Top100 점수 계산 Z-score 전환 + ROA 반영

**배경:**
- 현재: 백분위 → 0~25 정수 (정밀도 손실, 동점자 많음)
- 목표: Z-score 연속값으로 전환

**작업 내용:**

`Top100Service` ([Top100Service.java](../src/main/java/com/example/demo/domain/service/Top100Service.java)):
- `percentileScore()` 메서드 제거
- `ascRank()`, `descRank()` → Z-score 계산으로 교체
  ```
  Z-score = (값 - 평균) / 표준편차
  낮을수록 유리(PER 등): Z-score에 -1 곱하기
  ```
- ROA 팩터 추가 (높을수록 유리 → descRank 방향)
- `Top100` 엔티티 `score` 컬럼: `Integer` → `Double` 변경 필요

**업종 내 Z-score (1단계 완료 후):**
- 1단계에서 `induty_code` 수집 완료되면
- Z-score 계산 시 전체 평균 대신 동일 `induty_code` 그룹 평균·표준편차 사용
- 금융주(`induty_code` 600번대) 별도 풀 분리
