# 작업요약 — 스케줄러 활성화 및 시간 조정 (2026-07-13)

> `@EnableScheduling`/`@EnableAsync` 활성화 + 전체 데이터 수집·삭제 스케줄을 새벽 1~3시 안에 끝나도록 재배치

## 변경 내용

### 1. 스케줄러/비동기 활성화
- **DemoApplication**: `@EnableScheduling` 주석 해제
- **AsyncConfig**: `@EnableAsync` 주석 해제
- 이 두 개가 꺼져 있으면 `@Scheduled`/`@Async`를 아무리 걸어도 동작하지 않음 — 이번 변경의 전제 조건

### 2. FinancialScheduler
- 1분기/반기/3분기 보고서 수집·계산 스케줄러(`collectQ1`, `calculateQ1`, `collectHalf`, `calculateHalf`, `collectQ3`, `calculateQ3`) **주석 처리 유지** — 사용자가 의도적으로 꺼둔 상태 확인 완료, 변경 없음
- 사업보고서(연간, 11011) 수집·계산만 활성 상태

### 3. 스케줄 시간 재배치 (새벽 1~3시 안에 수집+삭제 완료)

| 시각 | 스케줄러 | 작업 |
|---|---|---|
| 01:00 (월-금) | ExchangeScheduler | 환율 수집 |
| 01:10 (월-금) | MarketIndexScheduler | 코스피 지수 수집 |
| 01:20 (월-금) | StockPriceScheduler | 주가 + 모멘텀 기준일 수집 |
| 02:00 (월-금) | Top100Scheduler | TOP100 스코어 계산 (주가 수집 완료 후) |
| 02:30 (매일) | Exchange/MarketIndex/StockPrice | 7일 이전 데이터 삭제 |
| 02:35 (매일) | Top100Scheduler | 7일 이전 TOP100 삭제 (다른 삭제 이후) |

FinancialScheduler(4/1 01:00·03:00), DividendScheduler(4/1 02:00), CompanyScheduler(1/1 01:00)는 연 1회 실행이라 원래도 범위 안에 있어 변경 없음. UserCleanupScheduler(매일 00:00)는 외부 데이터 수집과 무관해 변경 대상에서 제외.

### 4. 날짜 조회 로직 수정 (시간 이동에 따른 필수 변경)
- **ExchangeScheduler**: 기존엔 `fetchAndSaveExchangeRatesForToday()`로 "오늘" 날짜 환율을 조회했음. 환율은 당일 오전 11시경 고시라 새벽엔 데이터가 없어 그대로 두면 항상 실패 → "전 영업일자" 조회로 변경 (`fetchAndSaveExchangeRates(날짜)` 직접 호출)
- **MarketIndexScheduler**: 기존 `fetchAndSaveForToday()`도 동일 문제(코스피 지수는 장마감 15:30 이후 확정) → "전 영업일자" 조회로 변경 (`fetchAndSave(날짜)` 직접 호출)
- **StockPriceScheduler**: 원래도 전일 기준이었으나 월-금만 도는 구조라 금요일 데이터가 수집되지 않는 구멍이 있었음 (월요일 기준 "어제"=일요일이라 데이터 없음, 토요일 실행은 없음)
- **공통 처리**: 월요일엔 3일 전(직전 영업일인 금요일자)을 조회하도록 처리 — `DayOfWeek.MONDAY`면 `minusDays(3)`, 아니면 `minusDays(1)`
- 컨트롤러에서 쓰는 `fetchAndSaveExchangeRatesForToday()` / `fetchAndSaveForToday()`는 수동 트리거용으로 그대로 유지, 스케줄러만 날짜를 직접 계산해서 넘기는 방식으로 변경

## 참고

- `spring.task.scheduling.pool.size` 설정이 없어 기본값(스레드 1개)로 동작 — 위 시간표는 이 단일 스레드가 순서대로(01:00→01:10→01:20→02:00→02:30→02:35) 처리한다는 전제로 여유 시간을 뒀음. 주가 수집(01:20)이 API 재시도 등으로 오래 걸려도 계산(02:00)까지 40분 버퍼가 있어 순서는 보장됨.
- 컴파일 확인 완료 (`./gradlew compileJava`), 실제 배치 실행 테스트는 미진행.
