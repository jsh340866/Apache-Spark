## 1. Company.java — cascade 연관관계 추가

**파일 경로:** `src/main/java/com/example/demo/domain/entity/Company.java`

### 변경 내용
기존에는 `stockCode`, `corpCode`, `corpName`, `corpCls`, `createdAt`, `updatedAt` 6개 필드만 있었음.
아래 연관관계 6개가 새로 추가됨 (35~51번 줄).

```java
@OneToMany(mappedBy = "company", cascade = CascadeType.ALL, orphanRemoval = true, fetch = FetchType.LAZY)
private List<FinancialStatement> financialStatements;

@OneToMany(mappedBy = "company", cascade = CascadeType.ALL, orphanRemoval = true, fetch = FetchType.LAZY)
private List<StockPrice> stockPrices;

@OneToOne(mappedBy = "company", cascade = CascadeType.ALL, orphanRemoval = true, fetch = FetchType.LAZY)
private StockIndicator stockIndicator;

@OneToMany(mappedBy = "company", cascade = CascadeType.ALL, orphanRemoval = true, fetch = FetchType.LAZY)
private List<DividendInfo> dividendInfos;

@OneToMany(mappedBy = "company", cascade = CascadeType.ALL, orphanRemoval = true, fetch = FetchType.LAZY)
private List<Top100> top100List;

@OneToMany(mappedBy = "company", cascade = CascadeType.ALL, orphanRemoval = true, fetch = FetchType.LAZY)
private List<UserFavorite> userFavorites;
```

### 각 옵션 의미

| 옵션 | 의미 |
|------|------|
| `mappedBy = "company"` | 연관관계의 주인은 자식(외래키는 자식 테이블에 있음). Company는 읽기용 참조만 함 |
| `cascade = CascadeType.ALL` | Company 저장/삭제 등 JPA 작업이 자식에도 전파됨 |
| `orphanRemoval = true` | 컬렉션에서 자식을 remove()하면 DB에서도 자동 삭제 |
| `fetch = FetchType.LAZY` | Company 조회 시 자식은 실제로 접근할 때만 DB 조회 (성능) |

### cascade vs orphanRemoval 차이
- `cascade remove` → 부모(Company) 자체를 삭제할 때만 자식도 삭제
- `orphanRemoval` → 부모 컬렉션에서 자식을 꺼내는 것만으로도 DB에서 삭제

### 왜 추가했나
`DartCompanyCollector`에서 상장폐지 종목을 `companyRepository.deleteAllById()`로 삭제할 때,
연결된 FinancialStatement, StockPrice 등 6개 테이블 데이터가 cascade로 자동 삭제되도록 하기 위함.
이 설정이 없으면 외래키 제약조건 위반 에러가 발생함.

## 2. DartCompanyCollector.java — 스팩/리츠 필터링 + 상장폐지 삭제 방식 변경

**파일 경로:** `src/main/java/com/example/demo/domain/service/DartCompanyCollector.java`

### 전체 수집 흐름
```
1단계: KRX API → 현재 상장 종목 목록 수집
2단계: DART corpCode.xml → KRX 종목에 매핑되는 corpCode 추출
3단계: DB에만 있고 KRX에 없는 종목 → 상장폐지로 판단 후 삭제  ← 변경
4단계: KRX + DART 정보 합쳐서 Company 저장
```

### 변경 1 — 스팩/리츠 필터링 방식 개선 (isExcludedStock 메서드)

스팩(SPAC), 리츠(REITs)는 투자 수단이라 PER/PBR 같은 지표가 의미 없어서 수집 제외.

**기존 방식의 문제:**
`contains("리츠")` 방식이라 "메**리츠**금융지주", "블**리츠**웨이" 같은 일반 기업도 잘못 걸렸음.
이를 막기 위해 WHITELIST 상수를 별도로 관리해야 했고, 신규 상장 기업이 생길 때마다 수동 추가가 필요했음.

**개선 근거 — 법적 명칭 규칙:**
- 리츠: 부동산투자회사법상 상호 끝에 "리츠" 표기 의무 (예: NH프라임**리츠**, 이지스레지던스**리츠**)
- 스팩: 자본시장법상 상호에 "스팩" 또는 "기업인수목적" 포함 의무

실제 리츠는 항상 이름이 "리츠"로 끝나고, "메리츠"나 "블리츠"처럼 이름 중간에 "리츠"가 포함된 일반 기업과 구조적으로 구분됨.

**변경 후:**
```java
private boolean isExcludedStock(String corpName) {
    return corpName.endsWith("리츠")
            || corpName.contains("스팩")
            || corpName.contains("기업인수목적");
}
```

- `EXCLUDE_KEYWORDS`, `WHITELIST` 상수 제거
- 리츠는 `contains` → `endsWith`로 교체하여 오탐 원천 차단
- 스팩/기업인수목적은 이름 중간에 들어간 일반 기업 사례가 없어 `contains` 유지

### 변경 2 — 상장폐지 종목 삭제 방식 변경 (65~74번 줄)

**기존:** `deleteAllInBatch()` — DB의 Company 전부 삭제 후 다시 전부 저장 (비효율)

**변경 후:**
```java
List<String> delistedCodes = companyRepository.findAllIds().stream()
        .filter(code -> !currentListedCodes.contains(code))
        .toList();

companyRepository.deleteAllById(delistedCodes);
```

1. DB에 저장된 모든 종목코드 조회 (`findAllIds()`)
2. KRX 현재 상장 목록에 없는 것만 필터링 → 상장폐지 종목
3. 해당 종목만 선택 삭제 (1번의 cascade로 관련 테이블 데이터도 함께 삭제됨)

## 3. DartFinancialCollector.java — CFS/OFS 처리 개선, 통화 추적

**파일 경로:** `src/main/java/com/example/demo/domain/service/DartFinancialCollector.java`

DART API에서 받은 재무제표 데이터를 DB에 저장하는 수집기. 이번에 변경된 핵심은 `mapToDto()` 메서드 내부입니다.

### CFS / OFS란?

| 구분 | 설명 |
|------|------|
| CFS (연결재무제표) | 자회사 포함한 그룹 전체 재무 수치 |
| OFS (별도재무제표) | 해당 법인 단독 재무 수치 |

투자 분석 시 CFS를 우선 사용하고, CFS 데이터가 없는 기업(자회사 없는 소규모 기업)은 OFS를 사용합니다.

### 변경 1 — 중복 계정 처리 (145~154번 줄)

```java
// 변경 전: 무조건 덮어씀
cfsMap.put(name, value);

// 변경 후: 이미 있으면 건너뜀 (먼저 나온 값 = ord 작은 값 우선)
if ("CFS".equals(fsDiv) && !cfsMap.containsKey(name)) {
    cfsMap.put(name, value);
}
```

DART API가 같은 계정명을 여러 번 보내는 경우가 있어요 (예: 과거 정정 공시 포함). `ord`(순서) 작은 것이 최신 값이므로 먼저 나온 값을 우선 사용합니다.

### 변경 2 — 통화 CFS/OFS 각각 추적 (137~153번 줄)

```java
// 변경 전: 첫 번째 아이템에서 무조건 추출
String currency = items.get(0).getCurrency();

// 변경 후: CFS와 OFS 통화를 각각 추적
String cfsCurrency = "KRW";
String ofsCurrency = "KRW";
// ...루프 내에서 각각 갱신
```

CFS는 USD, OFS는 KRW인 기업이 있을 수 있어서, 어떤 fsDiv를 최종 선택했느냐에 따라 맞는 통화를 가져옵니다.

### 변경 3 — primary/fallback 구조로 리팩토링 (158~175번 줄)

```java
// 변경 전: getValue(cfsMap, ofsMap, "매출액")  → 항상 CFS 먼저 시도
// 변경 후: 선택된 fsDiv가 primary, 나머지가 fallback
Map<String, Long> primary  = "CFS".equals(finalFsDiv) ? cfsMap : ofsMap;
Map<String, Long> fallback = "CFS".equals(finalFsDiv) ? ofsMap : cfsMap;

revenue = pick(primary, fallback, "매출액")  // primary에서 먼저, 없으면 fallback
```

기존 `getValue()`는 항상 CFS 먼저였지만, OFS가 primary인 경우에도 올바르게 동작하도록 `pick(primary, fallback)` 구조로 변경됐습니다.

## 4. ExchangeRateApiService.java — 다통화 KRW 환산 메서드 추가

**파일 경로:** `src/main/java/com/example/demo/domain/service/ExchangeRateApiService.java`

한국수출입은행 API로 환율을 수집·저장하는 서비스. 이번에 **`getRateToKrw()` 메서드**가 신규 추가됐습니다.

### 왜 필요한가

DART 재무제표는 KRW가 아닌 통화(USD, JPY 등)로 기재된 기업이 있어요. `FinancialIndicatorService`에서 PER/PBR 등을 계산할 때 재무 수치를 KRW로 통일해야 하는데, 그 환율 변환을 이 메서드가 담당합니다.

### 추가된 상수 (38~47번 줄)

```java
// DART 통화코드 → 한국수출입은행 cur_unit 매핑
private static final Map<String, String> CURRENCY_UNIT_MAP = Map.of(
    "KRW", "KRW",
    "USD", "USD",
    "CNY", "CNH",       // DART는 CNY, 수출입은행은 CNH
    "JPY", "JPY(100)",  // 100엔 단위로 제공
    "IDR", "IDR(100)"   // 100루피아 단위로 제공
);

// 100단위 통화 - 조회한 환율을 100으로 나눠야 1단위 환율이 됨
private static final Set<String> UNIT_100_CURRENCIES = Set.of("JPY(100)", "IDR(100)");
```

JPY는 한국수출입은행이 "100엔당 몇 원"으로 제공하므로, 1엔당 환율로 바꾸려면 100으로 나눠야 합니다.

### getRateToKrw() 동작 흐름 (63~84번 줄)

```
KRW 입력 → 1.0 바로 반환
  ↓
CURRENCY_UNIT_MAP에서 cur_unit 변환 (예: JPY → JPY(100))
  ↓
DB에서 해당 cur_unit의 최신 환율 조회
  ↓
100단위 통화이면 ÷ 100 보정
  ↓
최종 환율 반환 (예: JPY 1엔당 9.xx원)
```

## 15. DividendInfo.java — company 연관관계 추가

**파일 경로:** `src/main/java/com/example/demo/domain/entity/DividendInfo.java`

### 변경 내용

```java
// 추가된 연관관계
@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "corp_code", referencedColumnName = "corp_code", insertable = false, updatable = false)
private Company company;
```

Company 엔티티에서 `cascade`로 삭제가 연결되려면 자식 엔티티에 `mappedBy`가 가리키는 필드가 있어야 합니다. `DividendInfo`는 `stockCode`가 아닌 `corpCode`로 Company와 연결되기 때문에 `referencedColumnName = "corp_code"`를 명시했습니다.

`insertable = false, updatable = false`는 이 필드가 DB 컬럼 관리에 관여하지 않도록 하는 설정 — `corp_code`는 이미 `@Id`로 선언되어 있어서 JPA가 이중으로 관리하지 않도록 막는 용도입니다.

## 16. Top100Service.java — 신규 추가

**파일 경로:** `src/main/java/com/example/demo/domain/service/Top100Service.java`

`STOCK_INDICATOR` 데이터를 기반으로 종목 점수를 계산해서 `TOP100` 테이블에 저장합니다.

### 스코어 계산 방식 (94~121번 줄)

4개 지표를 각각 **0~25점 백분위 정규화** 후 합산 → 총 100점 만점

| 지표 | 방향 | 이유 |
|------|------|------|
| PER | 낮을수록 고점수 | 낮으면 저평가 |
| PBR | 낮을수록 고점수 | 낮으면 순자산 대비 저평가 |
| ROE | 높을수록 고점수 | 높으면 수익성 좋음 |
| 부채비율 | 낮을수록 고점수 | 낮으면 재무 안정성 높음 |

```java
// 예시: 전체 1000개 종목 중 PER이 5번째로 낮은 종목
// rank=4 (0-based), n=1000
// percentileScore(4, 1000) = round((999-4)/999 * 25) ≈ 25점
```

### 중복 방지 (39~42번 줄)

```java
if (top100Repository.existsByBaseDt(baseDt)) {
    log.info("이미 존재합니다. 건너뜁니다.");
    return;
}
```

스케줄러가 실수로 두 번 실행되거나 수동으로 재실행해도 같은 날짜 데이터가 중복 저장되지 않습니다.
