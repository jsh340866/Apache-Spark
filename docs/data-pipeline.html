잡 간 데이터 전달은 전부 Parquet — 01~04번 사이에 MySQL을 거치지 않습니다. year=YYYY 파티셔닝으로 연도별 재실행이 가능하며, 이때 --conf spark.sql.sources.partitionOverwriteMode=dynamic을 빠뜨리면 기본 static 모드가 다른 연도 파티션까지 삭제합니다.
05번만 MySQL을 쓰는 이유 — 이 프로젝트의 원칙은 "MySQL을 잡 간 중간 데이터 전달에 쓰지 않는다"입니다. 05번은 이 원칙의 예외가 아니라 범위 밖입니다 — 다른 Spark 잡이 다시 읽을 중간 데이터가 아니라, 기존 ValuePick 프론트엔드/API가 조회할 최종 산출물을 서빙하는 단계이기 때문입니다.
